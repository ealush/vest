# Vest public roadmap

Vest is focused on becoming the dependable validation-state layer for complex TypeScript forms and workflows.

This roadmap communicates direction, not release guarantees. Core correctness and maintainability take priority over dates.

## Now: make Vest easy to evaluate

- Publish the validation-state category and honest tool-selection guidance.
- Ship problem-first Vest 6 documentation for async races, focused runs, dependencies, conditions, warnings, workflows, and server continuity.
- Maintain one runnable, compile-tested React architecture with React Hook Form, Standard Schema, a schema boundary, and a Next.js-style Server Action.
- Establish first-party conversion and AI documentation-quality baselines.
- Keep package metadata, examples, and upgrade paths current.

## Next: make Vest easy to encounter

- Propose useful Vest examples to upstream form and framework documentation.
- Publish a reproducible incremental-validation benchmark with explicit methodology.
- Add migration guidance for complex Zod, Yup, and Formik validation flows.
- Turn real user workflows into permissioned case studies.
- Create a contribution lane for examples, integrations, and documentation.

## Later: expand only where demand is demonstrated

- Framework-specific starters beyond the canonical React/Next.js architecture.
- Additional maintained adapters when Standard Schema is insufficient.
- A larger interactive playground and public recipe gallery.
- More benchmark scenarios and production-scale examples.

## Not a goal

Vest will not try to replace every schema validator, form manager, or native browser constraint. It will remain focused on validation behavior over time: focused execution, retained state, async lifecycle, dependencies, conditions, warnings, and browser/server continuity.

Feedback is most useful when it includes a real workflow, the current workaround, and the specific Vest capability or gap involved.
